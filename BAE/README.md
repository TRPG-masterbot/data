# 잠긴 종 · RAG TRPG 프로토타입

말과 행동을 입력하면 현재 게임 상태와 검색 근거를 바탕으로 NPC 대사와 장면이 이어집니다. 대화와 탐사로 알게 된 선택을 따라 의뢰·발견·주사위 판정·전투·귀환을 시험하는 프로토타입입니다.

## 실행

1. **BAE 폴더 전체**를 `TRPG-masterbot/data`의 `main` 최상위에 올립니다. 코드와 초상화 파일을 함께 교체해야 노트북의 버전 검사를 통과합니다.
2. `Output_Code.ipynb`를 새 Colab GPU 런타임에서 위부터 실행합니다. 설치 셀은 검색·화면 패키지와 Ollama 실행 프로그램을 준비하고, 준비 셀은 같은 런타임에서 Ollama를 시작해 `qwen3.5:9b`를 내려받습니다. L4를 권장하며 실제 배정은 가용량에 따릅니다.
3. 검색기와 Ollama 연결 준비가 끝나면 마지막 셀에서 플레이 화면과 임시 공유 주소를 엽니다. 저장소 파일을 받지 못하는 경우 같은 버전의 BAE ZIP을 선택할 수 있습니다.

첫 모델 다운로드·색인 준비와 준비 후 대화 응답에는 각각 별도의 시간이 걸립니다. 임시 공유 주소는 Colab 런타임이 실행되는 동안 사용할 수 있습니다. 생성 모델은 Ollama에서 실행하며 Python의 출력 코드는 HTTP로 요청과 응답을 주고받습니다.

### 로컬 PC에서 실행

[공식 Ollama](https://ollama.com/download)를 설치하고 실행한 뒤 터미널에서 `ollama pull qwen3.5:9b`를 실행합니다. 기본 연결 주소는 `http://127.0.0.1:11434`입니다. Python 패키지를 설치하고 노트북을 위부터 실행하면 같은 PC의 Ollama에 연결합니다.

Colab의 `127.0.0.1`은 Colab 실행 환경을 가리킵니다. PC에 설치한 Ollama와 자동으로 연결되지 않으므로 Colab에서는 노트북의 설치·준비 셀을 사용합니다. Python의 `ollama` 패키지만 설치하는 것으로 모델 실행 프로그램이 준비되지는 않습니다. 설치 방식은 [공식 Linux 안내](https://ollama.com/download/linux)를 따릅니다.

## 화면 사용

- **대화:** Enter로 전송하고 Shift+Enter로 줄을 바꿉니다. NPC 대사 옆의 작은 초상화로 화자를 구분합니다.
- **복사:** `대화 전체 복사`로 플레이어·NPC·GM의 공개 대화를 텍스트로 복사합니다.
- **이동·만남:** 일반 모드에서는 현재 관찰하거나 안내받아 알게 된 경로와 인물만 진행 선택에 표시합니다. 자유 입력도 발견 기록과 실행 조건을 확인합니다. 전체 지도·인물 선택과 바로 이동·만나기는 개발자 모드에 있습니다.
- **추천:** `[대화]`·`[행동]`·`[이동]`으로 구분한 다음 선택을 고를 수 있습니다. 새 응답을 기다리는 동안 이전 추천은 표시하지 않습니다. 직접 입력한 문장도 함께 사용할 수 있습니다.
- **판정:** 현재 가능한 행동 카드에서 조사·등반·공격 등을 선택합니다. 굴림이 필요하면 별도 패널에서 난이도·수정치와 실행할 행동을 확인하고 주사위를 굴립니다. 확정된 굴림·합계·성공 여부를 결과로 표시합니다.
- **전투·상태:** 전투 보드에서 적의 상태·라운드·행동·보너스 행동과 HP를 봅니다. 가방은 현재 휴대품만 작게 표시하고, 장착 장비·주문 슬롯·직업 자원은 캐릭터 정보에서 확인합니다. 의뢰에는 실제로 알게 된 내용만 표시합니다.
- **저장:** 게임 상태를 JSON으로 저장하고 불러옵니다. 개발자 모드의 이동·판정·전투 도구는 검사에 사용합니다.

## 코드 구성

메인 노트북에는 실행 라이브러리와 설정, 입력·두 RAG 연결, 대화 기억, 프롬프트 구성, 생성·검사 코드가 코드 셀로 들어 있습니다. 함수 정의와 실제 실행 순서를 같은 노트북에서 확인할 수 있습니다.

- **1~2번 셀:** 검색·화면 라이브러리와 Ollama 설치, 코드·게임 자료·초상화 버전 준비.
- **3~4번 셀:** 사용할 라이브러리와 모델·생성 설정.
- **5~8번 셀:** 입력·두 RAG, 대화 기억, 전달 데이터 확인과 프롬프트 구성.
- **9~11번 셀:** 모델 생성, 응답 점검과 화면 연결 함수 정의.
- **12~13번 셀:** 검색기 준비·Ollama 연결·모델 다운로드와 Gradio 화면 실행.

`src/output_code.py`와 노트북의 실행 코드는 패키지 생성 시 일치시킵니다. 반복되는 상태 표시·거래 검사·화면 이벤트는 해당 모듈에서 공통 처리합니다. 함수 이름과 입력·출력 관계는 유지합니다.

## 팀 통합 시 연결

이 폴더는 출력과 플레이 흐름을 함께 재현하는 프로토타입입니다. 통합 담당자는 `src/output_code.py`의 출력 함수를 공용 입력·RAG·엔진·화면에 연결합니다. `gameplay.py`·`game_ui.py`·`play_view.py`·`game/`는 현재 동작을 확인하는 기준으로 사용하고, 통합본에서 사용할 구현과 연결 범위를 맞춥니다.

### 준비와 호출

- **처음 한 번:** 현재 프로토타입은 `download_input_files()` → `prepare_input_backend(paths)` → `load_output_model()` 순서로 입력·두 RAG와 Qwen을 준비합니다. 통합본에서 입력·검색기를 이미 준비했다면 중복으로 초기화하지 않고, 아래 전달 자료를 구성하는 경로를 연결합니다.
- **공용 Ollama 재사용:** 같은 실행 환경에서 준비한 Ollama 서버와 `qwen3.5:9b`를 사용합니다. 생성 모델·토크나이저 객체를 Python에 따로 올리지 않습니다. 검색과 대화 기억에 사용하는 임베딩 모델은 생성 서버와 별도로 준비합니다. Ollama 연결 확인은 입력·두 RAG의 초기화를 대신하지 않습니다.
- **접속자별:** 대화 기억을 사용할 때 `create_memory_session()`으로 만든 ID와 NPC별 `history`를 유지합니다.
- **대화·규칙 질문:** `generate_from_handoff(payload, history, npc_name, engine_result)`를 호출합니다.
- **행동이 끝난 뒤:** `generate_action_result(payload)`로 확정된 결과의 대사·서술을 생성합니다. 행동 실행과 금액·물품·HP 변경은 공용 엔진이 담당합니다.

### 전달 자료

`payload`는 Python 딕셔너리 또는 JSON 문자열입니다. 대화 호출에 필요한 기본 필드는 다음과 같습니다.

필드 | 내용
---|---
`schema_version` | 문자열 `"1.0"`.
`player_input` | 비어 있지 않은 플레이어 원문.
`game_state` | 현재 엔진 상태를 담은 객체.
`retrieval` | `rule_results`·`scenario_results`·`memory_results` 목록. 각 검색 항목에 `text` 문자열, 선택 항목인 `metadata`에는 객체를 사용.

NPC 대화에는 화자의 `speaker_context`와 현재 `scene_context`, `player_snapshot`, 인물 관계·허용 지식이 담긴 `dialogue_context`도 맞춰 전달합니다. 화자 배경을 넣을 때는 `name`과 출처 `card_id`가 필요합니다. 현재는 `gameplay.py`의 `_generate_dialogue()`가 이 문맥을 보충하므로, 기본 JSON 필드만 전달하는 경로와 동일하게 취급하지 않습니다.

`dialogue_context.compact_speaker.profile_facts`에는 출처를 확인한 현재 화자 자신의 신상 사실을 전달합니다. 각 사실의 `id`·`subject`·`text`·`source_card_id`·`source_field`와 구조화된 `claims`를 유지하며, 관련성 검색 순위와 별도로 매 NPC 대화에 포함합니다. 범위로 주어진 나이는 범위로 보존하고, 정확한 숫자나 다른 인물의 정보를 보충하지 않습니다. 현재 자료에서는 `context_cards.json`의 `profile_fact_ids`가 연결 대상을 지정합니다.

`known_characters`에는 공개가 허용된 이름과 짧은 정체만 넣습니다. 현재 발언에 등장한 다른 사람의 공개 소개는 화자 자신의 프로필과 구분해 참고하며, 이름을 안다는 사실에서 친분·가족 관계·공유 경험을 추정하지 않습니다.

행동 결과 호출에는 실행한 `player_input`, `confirmed=True`인 `engine_result`, 비어 있지 않은 `public_narratives` 목록이 필요합니다. 공개 자료 항목마다 비어 있지 않은 `text`를 넣고, 반응할 NPC와 현재 장면·실제 상태를 함께 전달합니다.

### 반환과 화면 처리

화면에는 반환값의 `text`를 표시합니다. 두 생성 함수는 `speech`·`narration`과 `warnings`·`response_guard`·`generation_seconds`를 함께 반환합니다. 자연 문장 모드에서는 `speech`·`narration`이 비어 있을 수 있습니다. 대화 함수의 `suggestions`는 후속 추천이 별도로 생성되는 경로에서는 빈 목록일 수 있습니다.

후속 추천은 본문 뒤에 `generate_followup_question(payload, reply, history)`로 생성합니다. `recommendation_options`에는 `text`, `kind`(`dialogue`·`action`·`move`), 선택적인 `action_id`가 들어갑니다. 기존 문자열 목록인 `suggestions`도 함께 반환합니다. 화면의 구분 표시는 입력 문장과 분리하고, 행동 ID는 제공된 목록과 현재 엔진의 실행 가능 여부를 모두 확인한 뒤 연결합니다. 현재 `gameplay.py`는 이 확인과 늦게 도착한 추천의 폐기를 처리합니다.

생성 오류는 호출부에서 안내하고 성공한 답변만 대화 기억에 저장합니다. 부분 출력은 `output_stream(callback)` 문맥으로 연결하며, 행동 결과와 일부 응답은 점검 후 표시합니다. `response_guard`는 확인 가능한 충돌 검사 기록이며 전체 사실 정확도를 보장하는 값은 아닙니다.

함께 필요한 파일은 `response_guard.py`, `dialogue_projection.py`, `state_projection.py`, 인물·거래 보조 JSON이며, 상태 표시에는 `game.engine`의 금액 표시 함수도 사용합니다. `src/requirements.txt`와 위 파일 안내를 기준으로 의존 파일을 함께 연결합니다.

## 처리 흐름

입력 해석 → 엔진 조건 확인 → 필요한 검색과 기억 보충 → 화자·근거·최근 대화 구성 → Qwen 응답 → 화면 갱신.

실제 행동은 `Engine.available_choices()`로 조건을 확인하고 `choose()`로 실행합니다. `GamePlay`는 발견 기록과 대화 문맥을 연결하며, `play_view.py`는 이미 계산된 상태와 굴림 사건을 화면용으로 바꿉니다. 판정·명중 결과는 문장 재해석 대신 구조화된 사건 데이터로 전달합니다.

생성에는 Ollama의 `qwen3.5:9b`를 사용합니다. Python에서 `/api/chat`으로 대화 메시지를 전달하고, 생성 중 도착한 본문을 화면에 이어 표시합니다. [모델 태그](https://ollama.com/library/qwen3.5:9b)의 기본 양자화는 Q4_K_M이며 모델 파일은 약 6.6GB입니다. 모델 파일 크기는 실행 중 필요한 GPU 메모리와 같지 않습니다.

화면은 Gradio, 전달 데이터는 Python·JSON을 사용합니다. 룰 검색은 BGE-M3·Chroma·BM25·RRF, 시나리오 검색은 E5·Chroma와 장면·공개 조건을 사용합니다. 검색·기억의 임베딩은 SentenceTransformers·PyTorch·Transformers를 사용하므로 이 라이브러리는 생성 실행 방식이 바뀌어도 필요합니다.

새 게임은 시나리오에 준비된 광장 배경·공개 소문과 세라의 부탁으로 시작합니다. 첫 만남에는 시나리오의 시작 대사를 사용합니다. 이후 대화는 질문과 최근 문맥을 바탕으로 생성하며, 관련 공개 근거와 NPC의 인지 범위를 함께 참고합니다. 과거 생성 발언은 시나리오의 확정 사실로 취급하지 않습니다. 이동·판정·돈·아이템의 실제 변경은 엔진이 결정하고 생성 모델은 그 결과를 표현합니다.

지시어가 포함된 검색 질의에는 현재 NPC와 나눈 최근 두 차례 대화(최대 4메시지, 메시지당 110자)를 참고합니다. 독립적인 정보 질문은 현재 질문을 검색 기준으로 사용합니다. 사실 답변을 생성할 때는 과거 NPC 발언을 새 사실처럼 이어 쓰지 않고 출처와 확정 기록을 기준으로 합니다.

공개 인물 소개·확정 관계와 출처가 있는 자기 신상 정보는 관련 사실의 선택 순위와 별도로 유지합니다. 원본 공개 카드의 명시된 연령대를 대화 자료에 복원했으며, 공개 설정·개인 지식·현재 감각 관찰을 구분합니다.

기본 NPC 대화는 이전 발언을 인용 기록으로 묶고, 화자의 정체·관계·신상과 이번 질문의 출처 지식을 짧은 한국어 항목으로 정리합니다. 인용 기록 뒤에 확정 자료를 배치해 과거 생성 발언과 답변의 사실 기준을 구분합니다. 금액·수량·의뢰 조건은 엔진의 구조화된 값을 보존합니다. 신상 자료는 답변 대본이 아니며, 문장은 현재 발언에 맞게 생성합니다.

입력 사전 예산은 문자 수로 관리하며, 실제 입력·생성 토큰 수는 Ollama 완료 응답의 값을 기록합니다.

자기 가족 관계를 명시적으로 부정하거나, 제공된 관계로 확인되지 않는 자기 가족 관계를 단정하는 일부 표현을 검사합니다. 교정 대상이면 같은 근거로 한 번 다시 생성하고, 명확한 문제가 남으면 확정 응답으로 저장하지 않습니다. 자료로 확인되지 않는다는 판정이 그 관계가 거짓임을 입증하는 것은 아니며, 대명사·간접 표현과 모든 사실 오류를 판별하는 검사도 아닙니다.

생성 답변의 한자 혼입을 점검하고 필요한 경우 한국어로 교정합니다. 교정 후에도 출력 기준을 통과하지 못한 본문은 공개 답변으로 사용하지 않습니다.

말투 지침은 대화 상대에 대한 존대와 가족·제삼자 지칭을 구분합니다. 다른 사람을 부르는 표현은 현재 화자와 그 사람의 관계를 기준으로 구성합니다.

## 시나리오 진행과 공개 범위

플레이 자료의 `discover`는 실행한 행동·공개 카드가 알려 주는 장소와 인물을, `exit_labels`는 눈앞에 관찰되는 길의 표현을 기록합니다. 의뢰의 `visible_when`은 해당 의뢰를 알게 된 뒤에만 일지를 표시하는 조건입니다. 모델의 발언이나 플레이어의 추측만으로 발견 기록을 추가하지 않습니다.

세라의 수색 부탁을 수락하면 리나의 인형을 자동으로 맡습니다. 세라는 인형의 주인과 리나가 그 인형을 알아볼 수 있다는 의미를 먼저 설명하고, 그 뒤 할빅·메라를 다음 조사 상대로 안내합니다. 수락 전에는 인형 받기를 표시하거나 실행하지 않으며 이미 받은 인형은 중복 지급하지 않습니다. 실제 지급은 기존 인형 전달 행동 한 곳에서 처리하고, 수락과 전달의 실행 기록은 각각 보존합니다.

이 연결과 물길 조사·보고 의뢰, 회랑 입구 확인 후 귀환은 원문을 플레이로 잇기 위한 보완 데이터이며, 원문 인용과 구분해 출처·발동 조건을 기록했습니다. 공개 소개가 다른 인물의 개인 지식이나 숨은 사정을 모두 알게 하는 것은 아닙니다.

의뢰 수락 뒤의 생성에는 실행한 플레이어 행동, 요청자·수락자, 확정된 금액 변화와 공개된 다음 단계를 함께 전달합니다. 수행하는 플레이어와 반응하는 NPC를 구분하며, 실제 지급 상태와 생성된 문장의 표현은 별도로 확인합니다.

두 RAG의 검색 알고리즘은 유지합니다. 시나리오 검색의 장면·직업·플래그·방문 조건에 더해, 출력용 자료를 구성할 때 아직 발견하지 않은 단서와 만나지 않은 다른 인물의 상세 프로필을 제외합니다. 원본의 `text`·`gm_only_text`와 플레이용 `player_text`·대화 자료를 구분하며, GM 전용 정답·괴물·판정 카드를 NPC 대사에 그대로 넣지 않습니다.

엔진은 한 턴에 주문 시전으로 소비하는 주문 슬롯을 1개로 제한하고, Action Surge로 추가한 행동의 Magic 사용을 막습니다. 사망으로 게임이 끝나면 뒤따르는 이동·효과 적용을 중단합니다. 판정과 전투의 수치·성패는 생성 모델이 결정하지 않습니다.

## 검토 범위

앞선 실제 대화 검사에서는 출력 자료에서 누락된 신상 정보를 기억 문제로 설명하거나, 미제공 생활사와 현재 현상의 유무를 덧붙이는 오류가 남았습니다. 인물 정보 복원과 대화 자료 구성을 변경했지만, 이 변경만으로 자유 대화의 정확성이 해결됐다고 판단하지 않습니다. 인물 소개·관계 전달과 명시적 충돌 검사는 사실 오류 전체를 해결하지 않습니다.

아래는 앞선 게임플레이 버전에서 확인한 범위입니다. 실제 9B 생성 기록은 이전 Transformers 실행 방식의 결과이며, 이번 Ollama 전환의 응답 품질·속도 검증으로 취급하지 않습니다. Ollama 전환 후의 자유 대화는 직접 플레이하며 확인해야 합니다.

- **CPU 발견·공개 조건 검사 45항목 통과:** 미발견 인물·장소·행동 차단과 상태 보존, 실제 시나리오 안내를 통한 발견과 수락 자료 구성을 확인했습니다.
